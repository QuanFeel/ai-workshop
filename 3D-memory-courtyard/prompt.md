=== 提示词开始 ===

你是一名精通 Three.js 的创意前端工程师。请帮我做一个**送给最重要的人的 3D 互动回忆相册**网页，主题叫「记忆小院」。最终产物是**一个可以直接在浏览器打开就能玩的单文件 `index.html`**。请直接把完整代码写进 `index.html`，不要解释、不要拆分文件、不要让我再做任何配置。

## 一、硬性技术约束（必须全部满足）

1. **单文件**：所有 HTML、CSS、JavaScript、数据都写在一个 `index.html` 里，内联 `<style>` 和 `<script>`，不引入任何打包工具、框架或本地依赖。
2. **Three.js 用 CDN**：`<script src="https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.min.js"></script>`，用全局 `THREE`，不要用 ES Module / import。
3. **零资产也能跑**：生成出来后，在**没有任何图片/视频/音频文件**的情况下也必须能正常打开、能玩、控制台无报错。所有照片都要有 **emoji 兜底**：图片加载失败或没有配图时，自动显示该记忆点的 emoji，绝不出现裂图或卡死。
4. **运行方式**：直接双击或用 `python3 -m http.server` 打开都行；移动端（触摸）和桌面端（键盘+鼠标）都要可用。
5. **代码质量**：用现代原生 JS，错误要兜底（图片 onerror、音频 play 的 promise catch 等），控制台不能有未捕获异常。

## 二、整体体验（这是灵魂，务必还原这种感觉）

一个**低多边形、马卡龙色系、温馨可爱**的 3D 小院子，俯视偏斜的视角。访问者操控一个小人在院子里自由走动，院子里散落着几栋代表不同回忆的小建筑，每栋上方飘着一个会上下浮动的「？」标记。

- 走近某个建筑 → 自动弹出一张**回忆卡片**：标题 + 一段有温度的文字（打字机逐字显示）+ 照片轮播（多张时每秒自动切换，单张不切）。
- 部分回忆是**上锁**的：走近先弹出一道**解锁问题**（答对才能进入，可以是选项题或填空题），答对后该点的「？」变成名字标签，卡片解锁。示范数据里的解锁题必须是**小孩也能回答的简单题**，答案应该来自当前画面或常识，例如「院子中央是什么形状的喷泉？」「记忆点上方飘着什么符号？」；不要用私人暗号、电影梗、纪念日、复杂填空这类用户不知道就答不出的题。
- 院子里还藏着 **彩蛋**（比如一只到处溜达的小猫）：触发半径更小、更隐蔽，打开后是额外的惊喜卡片，但**不计入主线进度**。
- 顶部有进度提示「记忆 X / N ✨」，当**所有主线回忆都被打开**后，触发**完成态**：放烟花、屏幕中央浮现一段祝福语（带柔和的渐显动画），并播放一段完成视频（视频不存在则只显示祝福语，不报错）。完成弹层可关闭，关闭后人物还能继续自由走动。
- 全程有**背景音乐**，右上角一个按钮可以开/关，默认循环；音乐文件不存在时按钮仍可点击、不报错。

## 三、视觉与场景细节

- 天空浅蓝 `#9dd8f0`，加一层远景雾 `THREE.Fog`，让边缘柔和。
- 柔和光照：环境光 + 一盏带阴影的暖色平行光（开启 PCFSoftShadowMap）+ 一盏冷色补光；`ACESFilmicToneMapping`，曝光约 1.18。
- 院子地面是草地绿，中间一条/几条浅色小路；四周一圈**矮栅栏**围住活动范围。
- 点缀物：几棵**低多边形树**、成片的**小花**（随机颜色）、长椅、路灯，以及**院子正中一个"爱心喷泉"**之类的视觉中心。
- 建筑要**用基础几何体手搓**（Box/Cylinder/Cone/Plane 等组合），做成不同造型来区分不同回忆，例如：亭子 / 拱桥 / 城堡 / 教堂(婚礼) / 小房子 / 仿古街区。每栋用不同主题色。
- 中心可操控人物要做成**偏女性、精致、好看的主角**，不要是普通火柴人或中性小人。用简单几何体手搓一个低多边形「小公主 / 少女」造型：圆润头部、柔和五官暗示、深棕或栗色头发（可用球体/半球/小圆锥组合做刘海和长发）、粉色或玫瑰色上衣、蓬蓬裙或连衣裙（圆锥/截锥/圆柱组合）、小鞋子，并加入一个很小但明显的皇冠、蝴蝶结或发饰。整体比例要 Q 萌、马卡龙色、从俯视偏斜视角也能一眼看出是漂亮的女性主角。
- 人物移动时朝向移动方向，可以有轻微走路摆动；裙摆、头发或发饰可以有细微上下浮动/摆动，让角色更灵动。人物仍然必须只用 Three.js 基础几何体和材质生成，不依赖图片或模型资产。

## 四、交互细节

- **移动**：`WASD` / 方向键持续移动；**点击或触摸地面**则走向落点（射线检测地面，落点限制在院子范围内，可显示一个落点标记）。
- 移动要**限制在栅栏范围内**，并且**不能穿过建筑**（做简单的碰撞/半径限制即可）。
- **任何弹窗（回忆卡 / 解锁题 / 完成态）打开时，人物停止移动**；点击卡片外的空白处或关闭按钮都能关闭卡片（解锁题答对前也允许点空白关闭，只是不解锁）。
- **触发必须用「边沿触发」，不能用「每帧在半径内就弹」**（⚠️ 真实踩过的坑：否则关掉卡片的下一帧，人物仍站在触发半径内，立刻又被重新打开，表现为「弹窗关不掉」）。正确做法：给每个实体维护一个 `inRange` 状态，只有从「区外→区内」跨越的那一刻才弹一次窗；仍停留在区内不重复弹出；走出半径后把 `inRange` 复位，再走近才会再次触发。解锁题答错关闭后同理不再反复弹题。
- 走近判定必须考虑建筑碰撞体，避免出现「实体在建筑中心但玩家因为碰撞永远走不到触发半径内」的问题。推荐用 `触发半径 = 建筑碰撞半径 + 额外可触发边距`，主线边距约 2~3，彩蛋边距约 1~1.5；或者给每个点设置一个位于建筑外侧小路上的 `triggerPos`。总之每个主线回忆和彩蛋都必须能从可行走区域触发，不能有不可触达实体。
- 每个建筑周围至少留出一圈可通行空间，建筑之间、建筑与栅栏之间不要贴得太近；如果生成仿古街区/成排房子，也要确保玩家能从正面或侧边走近并触发。

**请用一套示范数据把页面填满，做到"开箱即玩"**：放 **6 个主线回忆**（其中 1~2 个上锁带题）和 **2 个彩蛋**（其中一个是小猫）。示范文案要温馨、像真的回忆（恋爱、旅行、婚礼、有娃这类主题都可以），`photos` 用形如 `pic/xxx/1.jpg` 的占位路径即可（反正有 emoji 兜底，跑起来不依赖真图）。上锁题目的示范问题必须简单到小孩看画面就能答，优先做选项题，避免用户被卡住。

七、Three.js 避坑清单（⚠️ 必须遵守，否则会白屏 / 卡在"正在搭建小院"）

> 以下都是真实踩过的坑。任何一个被违反，初始化阶段就会抛未捕获异常，导致渲染中断、加载遮罩永远不消失（页面只显示"正在搭建小院"），控制台报错。请逐条规避。

1. **`position` / `rotation` / `scale` / `quaternion` 是只读引用，绝不能整体赋值或 `Object.assign`。**
   - ❌ 错误（会抛 `Cannot assign to read only property 'position'`）：
     ```js
     g.add(Object.assign(cylMesh(...), { position: new THREE.Vector3(0,1.6,0) }));
     mesh.position = new THREE.Vector3(0,1.6,0);
     ```
   - ✅ 正确：先建对象，再用 `.set()` 或分量赋值：
     ```js
     const pole = cylMesh(...); pole.position.set(0, 1.6, 0); g.add(pole);
     // 或 pole.position.y = 1.6;
     ```
2. **初始化代码必须"零异常"**：场景搭建（建几何体、加灯光、放建筑）里任何一行抛错，都会让 `animate()` 永远不开始、加载遮罩永远不隐藏。**请把初始化主流程包在 `try/catch` 里**，`catch` 中至少把加载遮罩移除并在控制台打印错误，避免出现"卡在加载、毫无反馈"的死状态。
3. **十六进制颜色要用完整 6 位**：写 `0x556` 这种 3 位简写在 Three.js 里会被当成极小的数值得到近黑色，容易让人误以为没渲染。请一律写满 6 位，如 `0x556677`。
4. **几何体参数不能为 0 或负**：`CylinderGeometry`/`ConeGeometry` 的半径、`Box` 的边长等传 0 或负数会得到退化/不可见网格甚至报错；锥顶想做尖顶请用极小正数（如 `0.01`）而不是 0。
5. **`TorusGeometry` 等带 `arc` 参数的几何体**注意参数顺序（`radius, tube, radialSeg, tubularSeg, arc`），半拱桥用 `arc = Math.PI`，别把分段数和弧度写反。
6. **`CanvasTexture`/精灵贴图**：用 `<canvas>` 画文字做精灵（「？」、名字标签）时，`SpriteMaterial` 要 `transparent:true`；更新贴图后记得 `material.map.needsUpdate = true`（或换新 map 时 `material.needsUpdate = true`），否则标签不刷新。
7. **资源释放**：完成态烟花用 `THREE.Points` 循环生成时，销毁要 `geometry.dispose()` + `material.dispose()` 并从 `scene.remove`，避免长时间运行内存泄漏。
8. **音频/视频/图片一律兜底**：`audio.play()`、`video.play()` 返回 Promise 必须 `.catch(()=>{})`；`img.onerror`、`video.onerror` 里静默回退到 emoji / 隐藏视频，**绝不抛错**。
9. **不要用 ES Module 写法**：CDN 引入的是 UMD 版 `three.min.js`，全局 `THREE`，不要写 `import * as THREE` 或 `import {OrbitControls}`（CDN 这个包没带 examples 里的扩展，需要的控制/几何请自己用基础类实现）。
10. **移动端 canvas 触摸**：canvas 设 `touch-action: none`，`touchstart` 用 `{passive:true}` 取坐标，避免页面滚动/缩放干扰行走。
11. **触发检测必须边沿触发，否则"弹窗关不掉"**（⚠️ 真实踩过的坑）：不要在每帧只要"距离 < 触发半径"就 `openCard()`。那样关闭卡片后，人物仍在半径内，下一帧立刻重新弹出，用户感觉怎么点都关不掉。正确写法是给每个实体记录 `inRange` 布尔状态，只在 `inside && !e.inRange` 时弹一次（弹前置 `e.inRange = true`），`!inside` 时复位 `e.inRange = false`：
    ```js
    function checkTriggers() {
      if (modalOpen) return;
      for (const e of entities) {
        const inside = dist(player, e) < e.trigger;
        if (inside) {
          if (!e.inRange) { e.inRange = true; e.d.locked && !e.opened ? openQuiz(e) : openCard(e); return; }
        } else { e.inRange = false; }
      }
    }
    ```
12. **解锁后必须计入进度，别在答对回调里抢先置 `opened`**（⚠️ 真实踩过的坑）：上锁回忆的流程是「答对题 → 关题 → 延时 `openCard()`」。如果在答对回调 `onCorrect` 里就把 `e.opened = true`，而 `openCard()` 计进度的条件是"仅首次、未打开过"（`!e.isEgg && !e.opened`），解锁的回忆就会被跳过、永远不计入「记忆 X / N」，导致集齐也触发不了完成态。正确做法：`onCorrect` 只负责解锁（`e.d.locked = false`），把"标记已打开 + `openedMain.add` + 刷新 HUD + `checkFinish`"全部交给 `openCard()` 统一处理。
