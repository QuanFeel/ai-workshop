# 项目开发公约（可选模板）

> 按项目实际语言、框架、运行环境和交付方式补充。本模板只定义跨项目都适用的原则。

## 第一条：简单性与范围

- 只实现已确认的需求，不为未出现的问题提前设计。
- 优先使用现有项目能力和必要依赖，新增依赖要说明原因。
- 每次修改聚焦一个可检查目标，避免无关重构。

## 第二条：清晰与可维护

- 使用清晰的命名和模块边界，让后来的人能理解。
- 数据结构、配置、接口和关键约束应有对应说明。
- 异步、失败和异常输入必须有明确处理，不允许静默失败。

## 第三条：安全与数据边界

- 不把密钥、账号、私人资料或生产数据写入代码、日志或测试样例。
- 只读取和修改完成当前任务所需的文件、数据和权限范围。
- 发布、付款、删除和授权等操作遵循用户的明确授权及宿主平台规则；本模板不扩大权限。

## 第四条：质量与验收

- 使用适合当前项目的格式检查、静态检查、测试或构建验证。
- 关键路径要用真实或脱敏样例实际运行，而不只检查代码是否生成。
- 修改前先阅读相关现有代码；稳定节点保留可回退的版本记录。
