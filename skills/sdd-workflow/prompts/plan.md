# Step 2：技术方案 → plan.md

## 前置检查

读取 `{SPEC_DIR}/spec.md`；如果缺少必要的需求信息，按用户要求补齐后继续。

基于需求中的用户选择、假设和开放问题整理技术方案，并写入 `{SPEC_DIR}/plan.md`；审阅和继续推进依照用户授权及入口说明执行。

## 信息收集

先识别项目类型，再以对应的技术负责人视角制定方案：网页或前端、移动 App、桌面应用、后端服务、自动化脚本各自关注的运行环境不同。检查语言、框架、运行方式、已有代码和交付约束，只询问无法合理确定且影响方案的信息；若项目已有技术规则，优先遵循项目规则。

## 生成要求

1. **技术上下文总结**：明确项目类型、运行环境和技术选择。
2. **项目规则审查**：若项目有开发公约或约束，逐条检查方案是否符合。
3. **结构与边界**：明确模块、文件、服务或自动化步骤的职责和依赖关系。
4. **核心数据与交互**：按项目需要定义数据结构、接口、页面交互或命令输入输出。
5. **验证方式**：明确怎样启动、测试和验收核心路径。
