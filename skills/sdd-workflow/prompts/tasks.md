# Step 3：任务拆分 → tasks.md

## 前置检查

读取 `{SPEC_DIR}/spec.md` 和 `{SPEC_DIR}/plan.md`；缺少必要信息时按用户要求补齐后继续。

## 信息收集

根据用户要求和任务依赖划分阶段；只有在划分原则会影响交付且无法合理推断时才询问。

## 生成要求

1. **任务粒度**：每个任务只涉及一个主要模块、文件或步骤；不出现“实现所有功能”这种大任务。
2. **并行标记**：没有依赖关系的任务可标记 `[P]`；这不代表授权使用子 Agent 或额外资源。
3. **阶段划分**：按用户要求、交付重点和依赖关系划分。

## tasks.md 模板结构

````markdown
# [功能名称] 任务列表

## Phase 1：[阶段名称]

- [ ] **T1** [P] 建立核心数据、配置或输入定义
- [ ] **T2** [P] 建立界面、服务或脚本入口
- [ ] **T3** 实现核心处理逻辑（依赖 T1、T2）
- [ ] **T4** 接入核心输出和交互（依赖 T3）

## Phase 2：[阶段名称]

- [ ] **T5** [P] 补齐异常处理与必要提示

## 依赖关系图

```
T1, T2 → T3 → T4
T1 → T5
```
````
